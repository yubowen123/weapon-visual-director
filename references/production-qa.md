# 真实生成与视觉 QA

实际生成只在用户明确授权后执行。提示词校验、任务成功和视觉验收是三个不同层级，必须分别记录。

## 执行证据

每个真实任务记录：

- 模型与执行链
- 最终提示词或提示词包路径
- 任务号（服务返回时）
- 最终状态与返回 URL 数量
- 最终费用字段
- 下载后的本地文件路径
- 审核数组或拒绝原因，不记录任何密钥或带签名的临时 URL

Midjourney 的 `status=1` 只表示进入队列，`status=2` 且存在非空 URL 才表示成功。服务返回任务号后再变成 `status=3` 属于异步执行失败，不得描述为本地参数校验失败。

## 单件武器检查

逐张检查：

1. 只有一把武器；刀鞘不是第二把刀。
2. 武器和刀鞘完整入画，没有关键部位被裁切。
3. 刀刃数量、开刃方向、刀尖、握柄与鞘口不存在重复或矛盾。
4. `Preserve` 中的结构特征仍能从结果中识别。
5. `Avoid` 中的额外武器、人物、手、血液、Logo 和水印没有出现。

若结果出现额外刀具，把它标为负例，不因材质或氛围优秀而通过。

## GPT Image 2 卡片检查

固定检查文字和映射两组约束。

文字：

- 标题、副标题、三个局部标签、简介逐字核对。
- 不接受同音替字、生僻字误写或模型补写的编号、英文、印章。

局部映射：

| 局部窗 | 窗内必须显示 | 标注线起点必须落在 |
|---|---|---|
| 刃部 | 刀身表面与刃口 | 主武器的刀身金属 |
| 握柄 | 缠绳与木质握柄 | 主武器的握柄或缠绳 |
| 刀鞘 | 木鞘、铁箍或挂环 | 独立刀鞘的对应结构 |

标签、窗内内容和标注线起点必须三者一致。仅仅把线画到“附近”不算通过。

修正顺序：

1. 先尝试只移动标注线和起点。
2. 如果模型反复重置连线，但上、中的起点已经稳定，可交换两个局部窗内容与标签，让映射闭合。
3. 每次只做一个局部修正，并重新查看整张原图，防止文字或主体被连带改写。

## 测试集约定

测试定义放在 `tests/weapon-visual-director-cases.json`。真实运行清单放在 `tests/fixtures/{case-id}-run.json`，图片放在 `assets/evals/{case-id}/`。

运行清单至少包含：

- `case_id`
- `selected_reference`
- `artifacts[]` 的相对路径、模型、角色与人工结论
- 每个负例的 `expected_issues`
- 每个正例的 `expected_checks`
- MJ 任务状态和费用，但不得保存带签名的下载链接

运行：

```bash
python3 scripts/validate_visual_test_set.py tests/weapon-visual-director-cases.json
```

该脚本验证测试 ID、清单、图片路径、SHA-256、正负例标签与必须的 QA 字段；语义视觉判断仍需人工查看图片。
